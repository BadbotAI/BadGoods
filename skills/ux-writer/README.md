# 界面文案设计助手（UX Writer）

Skill ID：`ux-writer` ｜ 版本：2.3

界面文案设计助手让 AI 以 UX Writer 的身份写和审界面文案。它不是直接改句子，而是先定策略，再决定每一屏该出现哪些信息，最后才写和审。它主要针对 AI 生成的界面（vibe coding 的产物）里常见的文案问题。

## 它怎么工作

1. **定策略**：一句话定位、用户三问（懂什么、在什么情境用、来几次）、语气表、对象和动作词表。
2. **逐屏排信息**：每一屏只做一件事；候选信息分成常驻、按需、交给控件、不展示四档。
3. **写**：能用控件说的不用句子说；按钮是「动词＋对象」。
4. **审**：按屏做减法、逐句四问、查 AI 味和容器、陌生人通读。

## 它检查什么

| 分类 | 问题 | 例子 |
| --- | --- | --- |
| 说多了 | 旁白 | 「这里是输入框，不用看说明，直接输入即可」 |
| 说多了 | 自夸 | 「✨ 强大的智能记账，轻松掌控每一笔开销」 |
| 说多了 | 漏底 | 「已更新为绿色主题，并新增导出功能」 |
| 说多了 | 把按钮写成句子 | 「点击就会重新分类，不要就撤销」 |
| 说多了 | 填位置 | 每个菜单项都配一行描述，描述只是把名字展开 |
| 说多了 | 复述界面 | 输入框和按钮旁边写「填写编号，再点『查询』」 |
| 说多了 | 多处重复 | 同一句提示在首页、页脚、菜单、语音里各说一遍 |
| 说多了 | 氛围文案 | 菜单标题写成「从这里，开始记录生活」 |
| 说多了 | 状态旁白和过度声明 | 结果已经看得见，还弹「已开启」 |
| 说错了 | 立场错位 | 空态里罗列功能，像 PPT 在介绍产品 |
| 说错了 | 装错容器 | 一大段话塞进 tooltip |
| 说错了 | 一物多名 | 首页叫「账单」，按钮写「新增记录」，列表叫「流水」 |
| 说错了 | AI 味的表述 | 示例写成「把上个月餐饮那批挑 20 笔出来对一下，顺带看看还能不能再省点」 |
| 说少了 | 自创概念不解释 | 「本月呼吸值 62」 |
| 说少了 | 只写了顺利的时候 | 「出错了，请重试」 |

## 输入

以下任选其一：

- 界面代码（项目目录或单个文件）
- 界面截图（需要你用的 AI 能读图）
- 一份文案清单

## 输出

- **默认**：文案策略卡（定位、用户、语气表、词表，推测的部分会标明）；按屏的减法结果；一张审查表（位置、原文、问题、改为、理由），按严重程度排序；需要你确认的问题。
- **明确要求直接改，并且 AI 能改到代码时**：按审查表逐条修改，再通读一遍。
- **生成新界面时**：不单独出报告，直接把文案写对，交付时附文案策略卡。

## 使用示例

```text
使用 ux-writer，帮我审查 demo-app 这个项目里所有用户看得见的文案，按严重程度列出问题和改法，先不要改代码。
```

## 需要的工具

不需要额外工具或脚本。审查截图时，需要所用的 AI 支持读图。

## 限制

- 只改文案和文案所在的控件，不改功能、布局、配色。
- 已经确定的产品名、功能名、slogan 不会擅自改，只提建议。
- 不清楚某个自创概念的含义时会先问你，不会猜着写解释。
- 法律、隐私、付费相关文案只做清晰度建议，需要相关负责人确认。
- 规则和例子以中文界面为主。
- 规则是从真实界面的审查里总结的，示例全部是虚构的。2.3 版尚未做过系统测试。
