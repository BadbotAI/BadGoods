## V01 先确定证据与适用范围

- 先读取主 Skill 的审查范围、页面与实例清单，再按本文件选择检查；与逐组件手册组合执行。
- 核对用户指定的浏览器、设备、语言、主题、辅助功能和性能目标；已有明确约束时直接沿用。
- 在没有完整约束时先调查真实产品定位、现有配置和可见数据；记录工作假设，并继续不依赖缺失信息的检查。
- 将缺少移动端适配与“仅承诺桌面、指定最低宽度”区分；对后者检查低于边界时是否仍有可理解提示，不擅自扩成全设备支持。
- 将基础语义、键盘和输入法视为已支持交互的实现质量；不要仅以“不是出海产品”将其全部判为不适用。
- 只把实际运行结果记为已验证；将源码审阅、设计对比、自动扫描、模拟设备和真机测试分别标注。
- 在无浏览器、无设计稿、无目标账户、无读屏器或无法运行构建时，保留相应缺口；不得以推理替代通过结论。
- 按当前工具的能力说明和授权范围操作；不要假设某个浏览器 API、连接器、测试包或登录状态存在。
- 保留设计者已做出的交互决策；仅在证据表明不可用、互相冲突或超出实现能力时提出明确替代。
- 对测试用数据先使用隔离样本、现有 fixture 或已授权记录；不要为了观察反馈制造真实订单、计费任务或不可恢复删除。

### 建立证据记录

| 字段 | 记录内容 |
|---|---|
| 范围 | 页面、区域、组件实例、用户流程和对应版本 |
| 环境 | 浏览器及版本、系统、视口、DPR、输入方式、语言和主题 |
| 数据 | 样本来源、数量、关键边界值、用户角色与授权状态 |
| 操作 | 前置状态、具体动作、反向中断、等待条件 |
| 观察 | 实际布局、焦点、请求、控制台、性能轨迹或读屏反馈 |
| 结果 | 通过、确认失败、待验证、不适用，并写明原因 |
| 附件 | 截图、测试输出、相关源码和 trace 的可定位路径 |

## V02 建立逐页视觉基准

- 按每个页面定位可用设计来源：用户给出的截图、设计稿、已确认设计系统、现有产品约定。
- 在多个参考冲突时记录版本与具体冲突，优先沿用用户确认的当前目标；不要凭审美自行选一版后宣称还原正确。
- 没有参考时检查内部一致性、层级和可用性，将结论写为设计建议；不要给出“还原度 95%”等无依据数字。
- 对齐参考和实测的视口、缩放、内容、字体、主题与状态后再比较；不要把数据差异误判为 CSS 缺陷。
- 为每页建立默认、有内容、空白、加载、错误等实际可达状态的基准；仅有默认截图时标明其他状态没有设计依据。
- 对所有被审页面逐页检查内容结构、导航、主操作、信息密度、对齐关系和关键控件可达性。
- 对重要交互实例补充焦点、按下、忙碌、无效、只读等适用变体；不要仅截页面首屏。
- 根据已有原型检查滚动后的固定区、页底操作、弹层、展开内容和跳转后状态。
- 在截图工具可用时保存相同尺寸的基准与当前图；比较差异区域，并用实际 DOM 或样式证据确认根因。
- 仅遮罩时间戳等已知非确定内容；不要遮罩出错组件、跳动区域或反复不稳定的业务数据以获得漂亮差分。
- 对抗锯齿、系统字体渲染等环境噪声说明限制；不要把像素级误差一律升级为产品缺陷。

### 按层记录差异

| 层 | 检查动作 | 区分的问题 |
|---|---|---|
| 信息结构 | 核对标题、分组、阅读顺序、主次操作 | 区分内容缺失与单纯间距偏差 |
| 布局 | 检查容器、列宽、边距、对齐、溢出与固定区域 | 定位布局规则而非逐个像素补丁 |
| 字体 | 检查实际加载字体、字重、字号、行高、回退 | 区分字体未加载与字号写错 |
| 色彩 | 检查状态色、背景叠加、边框、焦点和主题 | 区分 token 错误与透明度组合问题 |
| 媒体 | 检查比例、裁切、清晰度、占位和加载后尺寸 | 区分素材问题与容器规则 |
| 状态 | 比较正常、错误、加载和禁用时的稳定性 | 区分样式缺失与状态模型错误 |

## V03 检查样式体系与真实内容

- 追踪样式来自 design token、共享定义、页面覆盖还是运行时内联属性；在最小正确层级提出修复。
- 比较同一语义在不同页面中的字号、间距、圆角、边框和状态色；保留确有业务理由的差异。
- 检查默认元素样式、重置样式、样式作用域和加载顺序；不要用不断追加选择器强度掩盖冲突。
- 检查图标本身尺寸与点击区域是否混淆；保证名称、图标和加载指示在各状态下对齐。
- 检查文本与容器使用固定高度时是否会裁切多行、错误信息和系统放大的文字。
- 检查 flex/grid 的最小尺寸、长词折行和溢出规则；对需要完整读取的内容提供实际入口。
- 检查 0、空字符串、null、缺失字段、长 ID、超长文件名和长 URL；不要将 0 当作无数据。
- 对金额、比率、日期和单位核对显示精度与接口含义；不要把显示格式替代存储和计算规则。
- 在已有多语言支持时检查最长文案、复数、CJK 换行、数字分隔和字体回退；在支持 RTL 时检查混排及逻辑方向。
- 检查真实内容排序和 DOM 阅读顺序；不要只用 CSS order 让屏幕顺序与键盘顺序分离。
- 对列表和表格检查空、单项、典型规模、长内容、部分错误；按用户数据和产品限制选规模，不默认造百万行。
- 在现有主题支持范围内逐一核对语义 token；避免全站颜色反转或硬编码局部颜色破坏主题。

## V04 检查微交互与中断

- 将反馈拆成“输入已被接收”“任务正在执行”“结果已确认”三类，核对文案和状态出现时机。
- 从实际事件观察反馈：按钮状态、焦点、布局、请求和最终结果；不要只检查 CSS transition 是否存在。
- 在异步操作前后分别观察可见反馈；确认同步重计算没有阻止忙碌状态被绘制。
- 检查 hover、focus-visible、active、selected 和 disabled 是否有各自作用，避免把焦点当成永久选中。
- 对关键操作在进入、执行和结束阶段分别尝试反向动作；只执行产品承诺且已授权的中断。
- 在过渡未结束时快速反向开关；检查动画结束回调是否把新状态覆盖成旧状态。
- 在任务失败后检查按钮、输入、反馈和焦点是否恢复，而非只隐藏 spinner。
- 在用户开始下一次操作后让上次结果返回，检查旧 toast、重置表单或自动跳转是否干扰新流程。
- 对取消说明实际取消对象：停止显示、断开传输或请求服务端取消；没有终态确认时不要显示已取消。
- 对动画时长遵循现有设计与实测需求；不要机械统一所有交互为某个毫秒值。
- 对自动滚动仅在用户正跟随内容或明确触发时执行；用户上翻阅读时保留位置并提供返回最新入口。
- 对无障碍偏好采用替代反馈保留状态含义；不要靠动画成为唯一成功或错误提示。

### 用动作矩阵检查反向路径

| 起始动作 | 在何时中断 | 核对结果 |
|---|---|---|
| 打开弹层 | 进入动画中关闭，再次打开 | 核对显隐、焦点、滚动锁与背景可操作性 |
| 发起查询 | 旧请求未返回时换词或清空 | 核对结果仍对应当前查询 |
| 提交表单 | 超时、后退、再次提交 | 核对保存状态、草稿和真实创建次数 |
| 拖拽移动 | 移出边界、松手前取消 | 核对原位置、当前选择和指针清理 |
| 开始流式任务 | 切会话、断网、点击停止 | 核对消息身份、恢复和实际任务状态 |
| 删除当前记录 | 删除成功后返回列表 | 核对焦点、页码和剩余选择 |

## V05 组织响应式组合

- 从支持范围生成每页测试矩阵；保留所有页面和适用状态的清单，再决定组合覆盖深度。
- 对每页先覆盖正常布局及各实际断点两侧；在关键布局转折处按需要检查断点值与相邻宽度。
- 对高风险实例增加窄宽度、长内容、错误或展开状态的组合，不只检查默认宽度下的 happy path。
- 对大组合空间采用代表性或成对覆盖，并声明未覆盖组合；不要把抽样表述为所有组合已通过。
- 在已有桌面支持时检查窄窗口、宽屏和浏览器缩放；在已有手机支持时再检查触摸、横竖屏与软键盘。
- 将浏览器设备模拟与真机验证分开记录；模拟视口和触摸不能证明真实输入法、浏览器外壳及软键盘行为。
- 对文本放大与重排按适用的 WCAG 条件检查；对本质需要二维表达的内容单独记录例外，不把全页横向溢出合理化。
- 在移动端检查地址栏展开收起、软键盘弹出、底部安全区域和视觉视口；先识别现有布局需求，再选择视口单位或能力适配。
- 在多个嵌套滚动区域中确认触摸、滚轮和键盘可把必要控件带入视野。
- 在旋转和 resize 后检查弹层锚点、表格宽度、图表尺寸和当前编辑内容；避免不必要地丢失状态。
- 对弹窗中的输入区检查“小屏 + 错误文案 + 软键盘”；对宽表检查“长单元格 + 固定列 + 缩放”。
- 对产品明确不支持的环境标注边界与实际降级表现；不要偷偷降低已承诺范围。

| 轴 | 选择方式 | 增加组合的条件 |
|---|---|---|
| 视口 | 使用声明的最小、典型、最大与布局断点 | 在控件布局或导航模式发生变化时增加边界 |
| 内容 | 使用空、典型、最长合法值、缺失与错误 | 在组件使用固定尺寸或截断时增加长内容 |
| 输入 | 覆盖键盘；按支持范围增加鼠标、触摸、输入法 | 在悬停、拖拽、快捷键、软键盘相关组件增加组合 |
| 偏好 | 按支持范围检查主题、减弱动态效果、缩放 | 在动画、主题覆盖、状态色或固定高度处增加组合 |
| 状态 | 覆盖当前控件可达的加载、错误、只读、禁用 | 在状态改变尺寸、焦点或可用动作时增加组合 |
| 身份 | 使用已授权的角色、所有者与非所有者测试数据 | 在实例根据权限隐藏、禁用或切换内容时增加组合 |
| 网络 | 使用正常、延迟、失败、重连的受控条件 | 在远程搜索、上传、流式和长任务中增加组合 |

## V06 检查层级定位与滚动

- 先标记每个滚动容器、固定区、sticky 区、transform 祖先、裁切容器和浮层挂载位置。
- 定位被遮挡原因：父级 overflow、层叠上下文、定位参照、viewport 变化或滚动同步；不要只增加 z-index。
- 对模态内容统一管理背景不可交互、焦点边界和滚动锁；对非模态浮层保留合理背景操作。
- 在嵌套弹层中核对最上层负责的 Esc、外部点击和焦点返回；避免一次事件关闭所有层。
- 在打开和关闭弹层后比较布局，检查滚动条出现消失造成的横移；根据现有布局选择稳定处理。
- 对固定页头、吸底工具栏与 cookie/系统横幅检查焦点是否被遮挡；将内容滚动到合理可见区域。
- 区分“焦点组件不被作者内容完全遮住”的 WCAG 2.2 AA 要求与更充分的可见性目标，避免混写等级。
- 在弹层内部滚至顶部和底部后继续滚动，核对背景行为符合产品预期。
- 对程序化 scrollIntoView 或滚动恢复检查选择的容器；避免把整个页面和局部区域同时跳动。
- 在历史数据前插、图片加载或字体替换后观察阅读位置；对聊天和日志采用明确的跟随与锚点策略。
- 在页面回退时核对实际产品承诺的筛选、页码、滚动位置和焦点恢复。
- 在拆分面板中检查最小宽高、可收起区域和键盘调整，保证主内容仍可完成任务。

## V07 检查输入法与编辑行为

- 对中文、日文、韩文等已支持输入法，在真实目标浏览器或可用测试环境检查组合输入，不用纯英文 fill 代替。
- 记录 compositionstart、compositionend 与键盘/输入事件的实际顺序；仅使用当前工具允许的事件观察能力。
- 在候选词尚未确认时按 Enter，核对不会误提交或发送；再按产品约定正常提交。
- 检查组合输入期间的实时校验、防抖搜索和格式化不会覆盖候选文本、重复请求或移动光标。
- 不把单行 isComposing 判断当作所有浏览器的完整修复；结合框架事件封装与目标浏览器行为验证。
- 不无条件增加废弃 keyCode 分支；只在明确兼容证据与支持范围内提出有说明的兼容处理。
- 对输入覆盖粘贴、剪切、撤销、重做、光标中部插入、选区替换、自动填充；在支持语音时增加语音输入。
- 将 Enter 提交与多行换行策略写清；不要吞掉系统、编辑器或辅助技术的合理快捷键。
- 对数字和格式化输入检查负号、小数点、未输入完成的分隔符等中间态；在确定时机解析而非强行重写每次输入。
- 在存在字数限制时明确用户可见字符、字节和 token 的区别；在需按字素计数时验证相关 API 或库的目标支持。
- 对密码和验证码允许产品规则支持的粘贴、管理器及自动完成；避免无必要增加记忆和重录负担。
- 在请求等待期间继续输入，确认上一次保存或发送成功不会清空下一段草稿。
- 对切页、切记录和组件重挂载检查输入值、光标和选区；区分业务要求的重置与意外丢失。

### 最小输入验收序列

1. 选择已支持输入法，输入有多个候选词的文字。
2. 按 Enter 确认候选，观察是否误触发送或提交。
3. 在文本中间插入一段内容，执行撤销再重做。
4. 粘贴一段含换行、emoji 或边界数值的合法样本。
5. 触发一次受控校验或提交失败，继续编辑并再次提交。
6. 核对显示值、请求值、光标、错误提示和当前实体身份。
7. 未获得真实输入法环境时，将该序列标为待验证，不以自动 fill 的成功替代。

## V08 完成键盘与焦点路径

- 从地址栏进入或从页面起点开始，使用键盘完成页面主要任务；记录必须使用鼠标才能继续的位置。
- 检查 Tab 顺序与阅读顺序、反向 Tab、可见焦点、跳过重复导航和页面标题。
- 区分焦点、选中、展开、悬停和当前路由；核对每种状态对应实际 DOM 与可访问语义。
- 对自定义复合控件先确定模式，再检查该模式的方向键、确认、取消和边界；不要全站统一拦截方向键。
- 对按钮优先恢复原生行为；对链接保留真实导航；避免为了样式使用不可聚焦 div 充当控件。
- 对禁用策略核对是否需要可被发现的原因；采用 aria-disabled 时仍需正确阻止动作。
- 打开模态时检查初始焦点，遍历边界并关闭；触发元素消失后将焦点移到合理下一步。
- 对非模态弹层不要无理由形成焦点陷阱；对确需编辑快捷键的编辑器提供可退出路径。
- 删除、移动、分页、筛选和内容重排后确认焦点依然存在且有上下文。
- 检查路由转换、错误摘要和后台更新不会把焦点意外移到 body 或不可见元素。
- 对多层 Esc 指定由当前上下文处理；避免正在输入时 Esc 同时退出编辑、关闭面板和跳离页面。
- 用可见结果和实际焦点节点共同确认；仅检查 tabindex 存在不足以证明键盘可用。

## V09 检查屏幕阅读器与语义

- 从实际 DOM 或可访问树检查名称、角色、值、状态和关系；不要根据屏幕截图推断辅助技术体验。
- 检查标题层级、landmark、列表、表格表头和表单分组；把有业务含义的结构用适当语义表达。
- 检查每个图标按钮、同名行操作和字段的名称；为重复操作提供当前对象上下文。
- 关联帮助与错误信息；不要让 placeholder 成为唯一标签，不要仅以红框表示错误。
- 检查 aria-expanded、aria-checked、aria-selected、aria-current 等值跟随真实状态，而不是固定模板值。
- 检查 ID 唯一性、label/description 引用与动态挂载；共享组件正确不代表调用处传入的 ID 一定正确。
- 在完整页面中检查 dialog 名称和背景处理；不要让 aria-hidden 区域保留用户正需要操作的焦点。
- 对成功、错误、结果数量与后台更新设置合适状态播报；不要把整个页面或每个 token 放进高优先级 live region。
- 对虚拟列表或懒加载内容检查阅读顺序、位置及总量信息；必要时提供适合业务的替代访问方式。
- 对图表、信息图、视频和复杂文档核对等价信息路径；不要用笼统 alt 替代关键内容。
- 在真实读屏器可用时记录具体软件与浏览器组合，完成主任务、表单失败和弹层打开关闭路径。
- 没有读屏器时可以记录 DOM 语义和自动扫描结果，但将实际播报、浏览模式和组合控件体验标为未验证。
- 将自动扫描的“未发现问题”限定为该扫描规则和被测状态；不要据此声明 WCAG 全面符合。
- 不从单页通过推出整站或整个业务流程通过；回到页面与流程清单核对缺口。

## V10 检查视觉偏好与动态效果

- 检查必要文本与真实背景的对比度；包含叠加背景、渐变、透明度与主题组合。
- 按适用成功准则区分普通文本、大字、非文本控件和不活跃元素；不要将一个阈值机械应用所有元素。
- 检查状态是否同时通过文字、图标或形状表达；不要只靠红绿颜色、闪烁或位置变化传达重要含义。
- 检查交互目标的实际点击区域及邻近间距；按 WCAG 2.2 AA 的 24×24 CSS px 要求及例外判断。
- 将 44×44 CSS px 标为更强目标或 WCAG AAA 相关要求，不要误报为全部控件统一的 AA 硬门槛。
- 在用户开启 prefers-reduced-motion 时检查视差、平移、缩放、自动滚动和循环装饰。
- 减少可能引起不适的运动，并保留可感知的状态反馈；不要无条件删掉表达任务活动的全部反馈。
- 在产品存在自动播放、轮播或持续更新时检查暂停、停止或隐藏等适用机制。
- 在目标平台支持 forced-colors 或高对比度设置时检查焦点、边框、图标与选中状态；不要仅根据默认主题推断。
- 放大文字并增加文本间距，检查遮挡、重叠、裁切和控件可达性；按实际适用条件记录例外。
- 对动画和媒体检查闪烁风险；遇到不确定效果时标注并按官方准则核查，不根据主观舒适感判通过。
- 将系统偏好模拟与实际系统设置测试分开记录，保留未获得的环境证据。

## V11 按架构检查SSR与公开页面

**适用条件：** 只有项目已经使用或确有业务需求时检查 SSR、预渲染、hydration 和公开搜索收录；不要以生产级为理由强制迁移。

- 先识别页面采用客户端渲染、服务端渲染、静态生成还是混合模式；记录路由和组件实际执行边界。
- 对纯内部后台优先检查登录、首屏可用、刷新和深链接；不要自动要求搜索索引、sitemap 或 SSR。
- 对 SSR 页面分别查看初始 HTML 和客户端接管后的结果；在相同数据和区域设置下核对结构与内容一致性。
- 检查时间、随机值、语言、时区、浏览器专属 API 和不合法结构是否造成初始输出差异。
- 对读取 window、document、屏幕尺寸或本地存储的路径确认执行时机；按照实际框架机制隔离浏览器能力。
- 不把某个 client 标记等同于“绝不在服务器生成初始 HTML”；按当前框架文档验证。
- 对 hydration 警告查明具体差异；不要统一 suppressHydrationWarning、关闭 SSR 或关闭检查来掩盖问题。
- 检查服务端与客户端重复取数、共享缓存和身份数据是否一致；对个性化内容核对缓存隔离。
- 对无脚本、脚本失败或延迟加载时的表现按产品承诺评估；不强制所有复杂应用实现完整无 JS 功能。
- 在公开收录需要时检查真实链接、唯一标题、描述、canonical 和正确状态码；验证不存在资源不会假返回成功。
- 承认 Google 可以执行 JavaScript；不要用“CSR 无法 SEO”作为架构论据。
- 对 SSR/SSG 建议写明预期收益、服务器成本、缓存与数据新鲜度约束，再给最小可行迁移范围。
- 在无法部署或访问对应生产构建时仅输出待验证项，不宣称静态源码足以证明 hydration 成功。

## V12 建立性能实测协议

- 先把“慢”定位为加载慢、响应绘制慢、接口等待慢、长时间使用变慢或布局不稳定。
- 为每个性能疑点绑定具体页面、动作、数据规模和设备，不生成脱离业务的统一跑分目标。
- 优先测项目实际生产构建；开发模式数据只用于定位，并明确其局限。
- 记录版本、浏览器、设备、网络、CPU 模拟、冷暖缓存、登录状态和样本；比较前后时保持条件可比。
- 根据风险选择合理重复次数，报告波动与代表性结果；不要挑最快一次证明优化有效。
- 先保留改动前基线，再对同一路径复测；没有基线时注明无法量化收益。
- 将工具结果、用户体感与后端耗时关联，识别瓶颈发生在哪一段。
- 对同页持续交互检查输入、搜索、切换、滚动和任务输出，不只测首页首次打开。
- 对长期使用检查重复打开关闭、切记录、后台恢复和任务完成后的资源回收。
- 在已有且授权的真实用户监测可用时按页面、设备和版本查看分布；不要未经授权新增第三方遥测。
- 缺少真实用户数据时用实验室结果定位风险，明确尚未验证线上分布。
- 对敏感界面只记录必要性能元信息，不把用户文本、文件内容或完整请求体上传给外部服务。

### 选择正确指标

| 问题 | 使用证据 | 避免误判 |
|---|---|---|
| 首屏关键内容晚出现 | 检查 LCP、资源链、图片字体、服务端响应与渲染 | 别把本地热缓存速度当首次访问 |
| 点击或输入不及时显示反馈 | 检查 INP 或对应交互的事件与主线程轨迹 | 别把 INP 等同接口从发出到返回的总时长 |
| 布局突然跳动 | 检查 CLS 及具体偏移来源 | 别只观察初次页面载入 |
| CPU 同步任务阻塞 | 检查长任务与函数调用、样式布局和绘制 | 别以设置 loading 状态证明它已显示 |
| 大列表与长文档卡顿 | 检查 DOM、渲染频率、查询和数据加工 | 别只以条目数量决定虚拟化 |
| 长会话占用持续增长 | 比较多次生命周期后的保留对象与资源 | 别将一次堆内存上升直接命名为泄漏 |
| 请求慢但界面响应正常 | 分解排队、网络、后端、缓存与数据转换 | 别用 memo 修复网络或后端耗时 |

- 引用 Core Web Vitals 时核对当前官方说明；良好阈值为 LCP 不超过 2.5 秒、INP 不超过 200 毫秒、CLS 不超过 0.1。
- 将这些阈值用于相应指标的第 75 百分位，并按移动与桌面分组；不要把单次工具输出当成真实用户 p75。
- 将实验室工具用于复现和回归，将真实用户数据用于观察实际分布；不要用 Lighthouse 一个分数代表全部性能。
- 不把 TBT 直接写成 INP；缺少真实交互测量时说明代理指标与实际交互指标的区别。
- 根据业务为导出、训练提交、文件打开等任务增加端到端指标，但清楚区分它们与 Web Vitals。

## V13 按证据定位性能机制

| 观察到的证据 | 按条件考虑的修复 | 一并复查的代价 |
|---|---|---|
| 非必要模块阻塞首次使用 | 考虑按路由或功能拆包、延迟重资源、优化资源优先级 | 检查首次打开该功能的等待、失败和重试 |
| 图片字体影响关键呈现 | 优化实际媒体尺寸、格式、加载策略与尺寸预留 | 检查画质、回退字体、裁切和布局稳定 |
| 同步计算形成长任务 | 按任务性质分块、让出执行机会或迁移 Worker | 检查消息传输、取消、数据复制与结果身份 |
| 局部输入触发大范围重渲染 | 缩小状态范围、稳定组件边界，再评估缓存 | 检查过期闭包、数据一致性与代码复杂度 |
| 真实规模下 DOM 或绘制过重 | 比较分页、服务端查询、增量渲染和虚拟化 | 检查焦点、读屏、查找、打印、选区和滚动恢复 |
| 数据请求重复或响应乱序 | 统一数据来源、适当去重与缓存失效、丢弃旧响应 | 检查身份隔离、更新后的新鲜度和离线语义 |
| 输出每小段都重排长文本 | 批量更新或稳定内容块，减少不必要重解析 | 检查中间状态、复制结果、读屏和用户滚动 |
| 媒体或区域尺寸不断改变 | 预留合理空间、稳定异步区及字体回退 | 检查空白空间、极端内容和小屏 |
| 生命周期后资源未释放 | 清理订阅、计时器、连接、对象 URL 和无界缓存 | 检查仍被其他实例共享的资源不会被提前关闭 |

- 将超过 50 毫秒的主线程任务作为长任务线索；结合真正交互延迟评估优先级，不把 50 毫秒当所有业务操作的总耗时上限。
- 不一律加入 memo、useMemo 或 useCallback；先提供重复工作的证据，再验证缓存收益和失效正确性。
- 不无条件虚拟化小列表；只有真实规模和测量支持时选择，并在每页实例复查其副作用。
- 不无条件把计算移到 Worker；先考虑主线程瓶颈、任务频率、传输成本与取消机制。
- 不为增加跑分移除用户需要的内容、语义、日志或功能；对产品取舍明确给出理由。
- 不将所有动画改为固定技术实现；按实际布局与绘制轨迹选择改动。
- 修复一个机制后复测原问题与相关回归；风险已解决且必要门槛已满足时停止扩展无关测试。

## V14 使用实际可用工具

### 先发现能力

- 从项目文件、锁文件和已有脚本识别技术栈；从当前工具目录识别浏览器、终端、截图和测试能力。
- 先遵循工具文档与会话授权，不用未公开的浏览器接口、私自假定的页面句柄或未经确认的登录会话。
- 复用现有测试运行器与已安装依赖；不因为示例使用 Playwright 就安装或迁移到 Playwright。
- 根据实际页面来源选择连接器、应用内浏览器或项目自己的测试环境；在工具协议要求许可的回退中遵守现有规则。
- 缺少某种能力时给出对应可执行步骤和未验证项；不要把示例代码、预期输出或计划当作实际结果。

### 用只读搜索发现候选

**适用条件：** 已有授权访问的本地源码和可用终端时，替换为实际源码目录后运行；把结果当定位线索。

```bash
AUDIT_SOURCE_DIR='src'
rg -n --glob '*.{js,jsx,ts,tsx,vue,svelte,html}' 'aria-live|aria-modal|aria-hidden|tabIndex|tabindex|onKeyDown|composition' "$AUDIT_SOURCE_DIR"
rg -n --glob '*.{js,jsx,ts,tsx,vue,svelte}' 'window[.]|document[.]|Date[.]now|Math[.]random|suppressHydrationWarning|setInterval|addEventListener|createObjectURL' "$AUDIT_SOURCE_DIR"
rg -n --glob '*.{css,scss,less,js,jsx,ts,tsx,vue,svelte}' 'z-index|overflow|position:|100vh|prefers-reduced-motion|outline' "$AUDIT_SOURCE_DIR"
```

- 先确认目录存在并调整项目扩展名；不要把没有匹配理解为没有问题。
- 阅读命中的定义和调用关系；确认事件、样式和生命周期确实在目标页面使用。
- 对危险模式判断上下文，例如 presence of aria-hidden 并不自动构成缺陷。

### 在已有浏览器能力下执行

1. 打开被审路由并设定真实前置状态；记录实际环境。
2. 通过已记录的工具 API 获取 UI、DOM 或可访问树，而非假设它们都可读取。
3. 使用能反映角色与名称的定位方式；针对重复实例增加上下文，避免点击了错误同名按钮。
4. 执行主动作和相关反向中断，等待实际完成条件而非任意固定长时间。
5. 核对焦点、可见结果、请求与控制台；在能力允许时保存截图或 trace。
6. 将每次观察回填页面和组件实例记录，保留未覆盖环境。

### 在项目已有自动化测试时执行

- 先读取 package 配置、锁文件、测试脚本和 runner 文档，再选择已存在的命令。
- 优先增加能复现确定缺陷的行为测试；不要为每个样式属性写与实现同义的测试。
- 对异步竞态使用现有 mock 或路由控制能力，以确定的返回顺序复现，不靠随机网络速度碰运气。
- 对模态检查打开、背景隔离、焦点顺序和关闭后的焦点；不要只断言 dialog 在 DOM 中。
- 对输入法保留人工或真机步骤；普通自动 fill 无法覆盖候选确认事件。
- 对响应式使用现有运行器支持的视口和偏好模拟，并明确它们的模拟属性。
- 对无障碍扫描记录工具、规则和页面状态；继续检查键盘与读屏路径，不把扫描当完整验收。
- 仅在命令真正完成并检查输出后报告通过；缺依赖、环境失败、跳过或超时均单列。

## V15 输出验证结果与重构方案

- 按页面、状态和单个组件实例归档结果，保留共享组件与实际使用处的映射。
- 对每个问题连接证据、用户影响、根因假设、具体机制、改动边界和可执行验收。
- 将视觉还原偏差、实际可用性缺陷、性能瓶颈和待决设计取舍区分，不用同一个“体验不好”掩盖不同问题。
- 对重构建议写明采用条件、收益、迁移范围、跨端依赖和回归风险；避免“全站换框架”之类无证据方案。
- 对只能静态发现的问题写清最小运行验证动作，避免承诺尚未验证的收益。
- 在已有性能基线时附前后可比较指标；没有可比条件时只描述观测，不编造优化百分比。
- 对可访问性结论列出被测辅助技术、页面和状态；没有完整符合性评估时不要宣称达到某个 WCAG 等级。
- 对用户请求“全面审查”核对清单覆盖率，而非只列发现数量；逐一解释尚未验证和不适用条目。
- 对无法访问的角色、设备、真机或生产构建保留明确的下一步，不把受限环境归咎于代码质量。

| 输出字段 | 必须包含 |
|---|---|
| 问题定位 | 路由、区域、实例、状态、相关定义与源码 |
| 验证级别 | 实际复现、静态确认、待验证或不适用 |
| 复现条件 | 环境、数据、角色、动作和中断时机 |
| 用户影响 | 哪个目标无法完成、错误结果或使用障碍 |
| 修复机制 | 在状态、语义、布局、渲染、协议或资源哪一层改动 |
| 验收门槛 | 哪条可观察结果才算修复，覆盖哪些使用处 |
| 保留限制 | 证据缺口、支持范围、测试替身与真实系统的差异 |

## 官方依据

- 用 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 核对等级、成功准则及例外，不根据自动扫描数目作完整符合性声明。
- 用 [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/) 选择具体控件语义与交互模式；按需阅读对应模式。
- 对焦点与模态核对 [WAI Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。
- 对环境范围核对 [MDN 跨浏览器测试](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Testing/Introduction)。
- 对软键盘与视口核对 [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)。
- 对输入法核对 [MDN KeyboardEvent.isComposing](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/isComposing)。
- 对动态偏好核对 [MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)。
- 对时间展示核对 [MDN Intl.DateTimeFormat](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat)。
- 使用 React hydration 时核对 [React hydrateRoot](https://react.dev/reference/react-dom/client/hydrateRoot)；其他框架使用各自当前官方文档。
- 对公开收录核对 [Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)。
- 对指标核对 [web.dev Web Vitals](https://web.dev/articles/vitals)，对主线程核对 [web.dev 长任务优化](https://web.dev/articles/optimize-long-tasks)。
- 使用项目已有 Playwright 时核对 [Playwright Assertions](https://playwright.dev/docs/test-assertions) 与 [Playwright Emulation](https://playwright.dev/docs/emulation)；不要据此假定当前环境已安装该工具。
