# UE 标注：写清布局、入口与操作结果

本规范是针对前端反向出 UE 的工作约定，不是某个组织发布的统一标准。目标是让读者能直接回答：页面由什么组成，哪些区域怎么伸缩/滚动，从哪里进入，操作后哪里发生什么变化。

## 调研依据

- [NN/g：Wireflows](https://www.nngroup.com/articles/wireflows/) 将页面布局与操作流程结合，适合说明同一页面里的动态变化。因此保留页面上下文，用控件触发的连线表达过程。
- [Figma：Prototype triggers](https://help.figma.com/hc/en-us/articles/360040035834-Prototype-triggers) 与 [Prototype actions](https://help.figma.com/hc/en-us/articles/360040035874-Prototype-actions) 区分触发方式和动作，也区分切页、打开/关闭浮层、滚动等。因此标注不能把所有变化笼统写成“跳转”。
- [MDN：height](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/height) 与 [overflow](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow) 解释尺寸约束和溢出处理。因此必须分别核对高度规则、最大高度、实际溢出和滚动归属；一个截图里的像素高度不能单独证明定高。
- [GOV.UK：Recover from validation errors](https://design-system.service.gov.uk/patterns/validation/) 强调错误原因和如何修正。因此异常标注应交代错误出现位置、阻止什么操作、如何恢复；按原产品实际行为记录，不把该系统的具体实现要求强加给其他产品。

## 生成顺序

1. **识别板块。** 先读取实际可见 DOM/组件，按业务名称划分页头、筛选、列表、详情、操作栏、浮层等。不要把每层 div 都列成板块。
2. **提取容器规则。** 核对最终生效 CSS、flex/grid 父子约束、运行尺寸和溢出。需要判断自适应时，对比至少两个视口或内容量。只看到截图时，把尺寸标为“当前画面”，不要推断固定规则。
3. **建立操作表。** 读取真实可见控件名称与实际处理逻辑，记录来源、触发控件/方式、条件、动作类型、目标页面/区域/状态、结果与返回。
4. **先形成结构化事实，再写短句。** `annotation.layout` 保存布局句；`entries` 引用来源与触发边；`transitions` 保存具体 `trigger / effect / from / to`；仅在影响理解时增加 `rules`。事实依据继续保留在模型/报告中。
5. **同一模型生成 HTML 和 Figma。** 相同 ID 对应相同含义；页面地图、说明链接、返回路径都引用真实目标。新增说明不是新增已验证功能。

## 每页默认展示

**布局：2–3 条。** 先列板块顺序/分栏，再说明关键尺寸与滚动。优先交代这些有决策价值的差别：

- 固定值、最小/最大值、内容撑高、占满剩余空间分别是什么；宽窄变化时如何处理。
- 整页滚动还是指定容器滚动；横向还是纵向；标题、筛选、表头、底栏是否随动。
- 弹窗/抽屉覆盖哪里，宽高受什么限制，长内容如何访问。

“留在原位”不等于 CSS `position: fixed`。例如弹窗标题与底栏可以是滚动正文之外的普通 flex 子项，标注其表现即可。

**入口：来源 + 控件 + 结果。** 如“订单详情 → 点击『上传文档』→ 打开上传弹窗”。核对状态的直接入口应写“待上传队列 → 点击『上传并解析』→ 原弹窗切换核对步骤”，不能只写“通过界面操作进入”。

**交互：一行一个规则。** 用“条件（如有）＋点击/输入什么 → 哪个页面/区域以什么方式变化（目标 ID）”。区分切页、开/关弹窗、切页签、展开、局部刷新、校验、暂存和确认写入。返回/关闭也属于关键路径。

**状态规则：仅写重要的 1–2 条。** 如勾选不保存、确认才写入、只读时禁用、错误提示位置和恢复方式。没有额外规则时省略该栏目；不要填“本页无写入”“未单独验证”等占位句。影响业务判断但未核实的规则明确列为待确认。

全局导航、公共页头等规则集中定义一次；各页优先写差异。实现函数、实体英文清单、证据标签、隐私说明与测试过程放在模型或随附报告。避免重复页面标题作为用途。

## 示例：上传核对

布局：居中弹窗，由订单/步骤、文件切换、字段对照表和操作底栏组成。宽 760px，高度随内容，最高为视口高−48px；仅中部滚动，标题/底栏保持可见。

入口：待上传队列（ORD-08）→ 点击“上传并解析”→ 原弹窗进入核对步骤。

交互：点击“确认更新 3 项”→ 原弹窗显示已采用结果（ORD-10）；点击右上角 × → 关闭弹窗，保留订单详情（ORD-02）。

状态：勾选仅改变待采用项；点击确认才保存选中字段、增加版本并记录历史。

## 验收

读者应能从标注找到具体区域、触发控件和目标；“固定高度/内部滚动”等结论有 CSS 或运行依据。每条目标可定位，局部变化没有被画成虚构的新页面。隐藏内容不误当可见板块，发现源原型裁切等缺陷时标记现状，不悄悄美化成不存在的行为。


## 在画布和导出图中表达

- 标注分为布局、入口、交互三个页签。布局短句优先说明板块和容器约束；入口与交互改用带缩略图的流程卡。
- 入口：来源页标签/缩略图 → 控件与条件 → 动作类型 → 当前页。交互：控件与条件 → 动作类型 → 目标页标签/缩略图。不能把来源页画在箭头终点。
- 动作类型用具体短语：打开右侧抽屉、原弹窗切换步骤、切换下方页签、局部更新、保存所选字段。用颜色辅助区分时仍保留文字。
- 画布总览避免文字重叠；缩小后隐藏无法容纳的标题，按需显示完整名称。编号使用标签，避免与页面名争夺层级。
- UE 导出图展开全部标注；不要只导出用户当前打开的页签。数据变更示例说明当前选择条件，不能把“全部采用”的数值当作所有选择下的通用结果。
