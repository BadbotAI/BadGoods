# 走查经验（坑清单）

这份清单是这个 Skill 最值钱的部分：通用方法谁都查得到，这里记的是实际走查中踩出来的坑。

- Step 4 设计用例时用来查漏，Step 6 执行时逐条对照。
- Step 9 复盘时，经用户确认后追加到对应主题下，格式：`- 经验内容（来源：<走查目标>，<YYYY-MM-DD>）`。
- 只写可操作的经验（「怎么测、看什么」），不写空泛的原则；同一条经验不要重复记。

## 通用高频坑

- 每个按钮都快速连点两次，检查是否重复提交。
- 每个输入框都试：空、只有空格、超长、特殊字符和表情、粘贴带换行的文本。
- 登录后按返回键、刷新页面，检查登录状态是否保持。
- 操作中途断网，检查是否有提示、恢复后数据是否丢失。
- 列表要看 0 条、1 条、很多条（触发分页）三种情况。
- 错误提示要说清楚错在哪、怎么改，且不能清空用户已填的内容。
- 未登录时直接输入后台页面 URL，检查是否被拦住。

## 补充经验

> 以下为作者在实践中补充，按主题归类。

### 提交与并发

- 按钮进入 loading 后必须禁用；只改文案不禁用，连点仍会重复请求。
- 提交失败后重试前，先确认第一次是否其实已成功（超时场景常见「报了错但数据已落库」）。
- 两个标签页同时编辑同一条数据，后保存的是否覆盖前者；是否提示版本冲突。
- 关闭弹窗再打开，上一次的校验错误和已填值是否残留。

### 输入与校验

- 校验时机：失焦才校验的字段，直接点提交是否也能拦住。
- 校验错误后修改输入，错误提示是否立即消失，还是提交后才更新。
- 最大长度用中文、emoji、粘贴验证，字符计数按 code unit 还是字符可能不一致。
- 金额/数量字段试负数、0、小数位超限、粘贴带货币符号和千分位。
- 浏览器自动填充账号密码后，前端校验状态可能仍是「未填」。
- 粘贴富文本到纯文本输入框，是否带进隐藏格式或换行。
- 输入被静默过滤或截断（如手机号框输入字母直接消失）却没有任何提示，用户会以为键盘坏了；要单独记一条体验问题。
- 中文输入法打拼音的过程中就触发校验或提交，是常见问题。

### 登录与权限

- 会话过期时正在填表单，提交后是否跳登录、回跳后内容还在不在。
- 退出登录后按浏览器返回，缓存页面是否还能看到敏感数据。
- 直接改 URL 里的资源 id / 用户 id，是否越权看到他人数据。
- 无权限角色登录后，菜单隐藏了但接口是否也做了校验（隐藏不等于拦截）。
- 「记住我」与不勾选时的会话时长是否真的有区别。

### 列表与导航

- 在最后一页删除唯一一条后，停留在空页还是回退上一页。
- 排序/筛选后页码是否重置；刷新后筛选条件是否保留。
- 返回键恢复列表时，滚动位置和选中状态是否正确。
- SPA 路由下刷新子页面是否 404（服务端未配置 fallback）。
- 分享带查询参数的链接，打开后状态是否一致；非法参数是否白屏。

### 视图与可用性

- 320px 窄屏和 200% 缩放各看一遍，重点看表格、按钮组、弹窗。
- 弹窗打开后 Tab 是否跑出弹窗，ESC 是否关闭，关闭后焦点是否回到触发按钮。
- 图片 404 是否有占位；头像/缩略图缺失是否撑破布局。
- 长用户名、长标题、长错误文案是否溢出或遮挡操作按钮。
- 颜色不是唯一的状态区分手段（禁用/错误状态是否有文字或图标）。

### 证据与记录

- 截图要包含判定依据：错误提示、输入值、URL、关键数据。
- 只截「正确状态」不能证明错误状态；异常用例要截异常现场。
- 控制台报错和失败请求要同时记，接口 200 但业务 code 失败也常见。
- 判定前先刷新一次，排除缓存和上一条用例的残留状态。
- 上一条用例产生的数据会影响下一条，必要时重置环境再执行。

### 账号与环境

- 练习站常提供故意注入缺陷的账号（例如 saucedemo 的 problem_user、error_user 等）。先用正常账号建立基线，再逐账号对比；预设缺陷单独标注，不计入产品通过率。
- P0 要在所有可用的账号角色上各跑一遍，账号差异本身就是等价类维度。
- 静态托管（GitHub Pages、OSS、CDN）返回的 404/302/缓存头属于平台行为，先看响应头（server、x-cache）再决定是否记缺陷。
- SPA 未登录时，接口返回 401 是正常的拦截，不是缺陷；要看的是页面有没有正确跳转或提示。
- 演示环境的「严重/致命」按「如果发生在生产会怎样」评估，并在报告中说明。

### 敏感操作与数据

- 登录要短信验证码、页面涉及健康/金融/身份信息时，先确认有没有测试号和测试数据，没有就只走查登录前和静态部分。
- 测试数据用明显虚构的值（如 13800138000、测试用户），方便事后清理，也不会误伤真实用户。
- 截图前看一眼画面里有没有真实手机号、身份证、Token，有就打码或换数据重截。

### 测试方法有效性

- 连点要用真实双击或 ≥100ms 间隔的两次点击；同一 tick 的两次 JS click 可能被框架合并，不能证明防重。
- 断网要测有网络依赖的动作（登录、结算、搜索）；纯前端加购在断网下成功，不代表网络容错通过。
- 元素 ref 失效、eval 语法错误、误点导航都属于执行失败，不是用例结果；先恢复页面再重跑并记录重试。
- 每条用例前重置账号、业务数据（购物车、草稿等）、Cookie/localStorage、URL、排序，避免上一条污染下一条。
- 「通过」之前先确认操作真的触发了要验证的路径（比如请求真的发出去又真的失败了）；没触发就是「未执行」。
